# CipherLink 5.0.1

在不安全的聊天软件里传递端到端加密消息和文件。双方先互换**公钥**，之后互发只有对方能解开的**密文**；
聊天软件和任何中间人只能看到密文。没有网络权限、没有服务器，所有加解密都在手机本机完成。

## 编译

1. Android Studio（最新稳定版）→ **Open** → 选这个目录 → 等 Gradle Sync。
2. 工程沿用 4.1.1 的构建配置：AGP 9.4.0、Gradle 9.6.0、JDK 17、compileSdk/targetSdk 36、minSdk 26、
   依赖仅 `com.google.zxing:core:3.5.4`（AGP 9 自带 Kotlin，无需另加 Kotlin 插件）。
3. 接手机 **Run**；或 `Build → Build APK(s)`。

> 说明：包里的 `gradlew` / `gradle-wrapper.jar` 是 4.1.1 带来的精简版。在 Android Studio 里编译不受影响
> （Studio 按 `gradle-wrapper.properties` 自己下载 Gradle）。若要用命令行，先在 Studio 终端执行一次
> `gradle wrapper --gradle-version 9.6.0` 生成官方 wrapper。

覆盖安装 4.1.1 时，**本机密钥、联系人、启动密码都会保留**（存储键名与 4.1.1 一致）。

## 使用流程

1. 第一次打开 → 触摸/滑动约 3 秒收集随机性 → 生成 RSA-3072 密钥。
2. **联系人**页 → 「分享公钥」发给对方；把对方发来的 `CL2P.` 公钥卡「添加联系人」（粘贴、剪贴板、或扫公钥二维码截图）。
   首次交换请电话/当面核对双方「指纹」。
3. **消息**页：选收件人 → 输入文字 →「加密并复制文本」→ 去聊天软件粘贴发送。
   - 「二维码拼图」：把密文拆成多张二维码拼成一张图，可保存/复制/分享。
   - 「📎 附件」：图片、压缩包等任意文件（≤ 10 MB）→ 加密成 `.clink` 文件 → 在聊天软件里当"文件"发送。
4. 收到密文：复制后点「粘贴并解密」；收到二维码图：「最近截图」或「选择二维码图片」；收到 `.clink`：用 CipherLink 打开/分享给它。
   解密结果存在**收件箱**（本机加密保存，最多 100 条）。

不打开 App 也能用：
- **通知栏（全 App 唯一一条通知）**：加密发送 / 解密 / 解密剪贴板 三个按钮，解密结果也显示在这里。
- **悬浮窗**：可拖动的悬浮球，点开是发送/解密面板。
- **长按选中密文 → "CipherLink 解密"**，或把二维码图 / `.clink` 文件"分享"给 CipherLink 解密；
  任意 App 里"分享 → CipherLink 加密发送"可直接加密文件或文字。
- **自动解密**（设置里开启）：监听剪贴板、监听新保存的二维码图片。

## 5.0.1 更新（只改显示层，加解密/去重/收件箱等核心逻辑未动）

- **按钮显示不全**：按钮高度完全由文字撑开、没有最小高度，圆角矩形被压得过扁；现在按钮最小高度 44dp，
  内边距在设置背景之后再设置（避免被背景重置），卡片、输入框、标签也统一了设置顺序。
- **只用一条通知**：App 里只剩一条通知（固定 ID），同时包含「加密发送」输入框、「解密」输入框、
  最新的解密结果和「解密剪贴板」按钮。
  - 自动解密成功：直接更新这一条并弹出，新消息替换旧消息，不再另起一条。
  - 「自动解密运行中」「悬浮窗已开启」两条状态通知取消——Android 要求前台服务必须有通知，
    所以它们改为共用这一条；两个服务都停止、且没有开启"通知栏快捷输入"时，这条通知会自动消失。
  - 通知用高重要性但静音的通道，并用 BigText 展示完整内容。注意：Android 不允许 App 强制展开通知，
    能做的是把它排在通知栏最上面并放出完整文字；部分系统在 设置 → 通知 里有"默认展开通知"类选项。
  - 原来悬浮窗通知上的"关闭悬浮窗"按钮，挪到了悬浮窗面板顶部。
  - 原来结果通知上的"复制"按钮取消（一条通知最多稳定显示 3 个按钮）；点通知进入收件箱即可复制。

| 通知栏结果静默、不弹出 | 结果显示在唯一的那条通知里并弹出（新消息替换旧消息，不堆叠）；锁屏隐藏内容 |

## 协议与安全

- 加密：RSA-3072-OAEP（SHA-256 / MGF1-SHA1）封装随机 AES-256-GCM 密钥；SHA256withRSA 对头部、密文、发送方公钥签名。
- 兼容：文本密文 `CL2M.` 格式与 4.1.1 完全一致（原保留字节现用作内容类型：0 文本 / 1 附件，已被签名保护）。
- 每条消息带发送方公钥；已保存的联系人按指纹锁定身份，未保存的发送方会标"未保存的发送方"，可一键保存。
- 二维码：先加密签名，再分片（`CL2Q.`），收齐后整包校验才解密。
- 私钥由 Android Keystore 的 AES-GCM 密钥保护；收件箱与附件落盘前再加密一次；无网络权限。
- 首次建钥的触摸/时间戳只是**额外**熵，系统 `SecureRandom` 仍是主随机源（Android 的 RSA 生成器不一定使用传入的随机源，这点不要神化）。

## 已知限制（请知悉）

1. **Android 10+ 不允许后台 App 读取剪贴板内容。** 所以"后台监听剪贴板"在多数手机上无法在你不操作时生效，这是系统限制。
   做法：App 在前台时自动检查；其余场景点通知栏/悬浮窗的「解密剪贴板」，一步完成。
2. 监听二维码图片需要"全部照片"权限（只选了"部分照片"时无法持续监听）。
3. 部分国产 ROM 会杀后台服务：设置里有「后台保活设置」入口。
4. 通知栏、悬浮窗、「解密剪贴板」为了"无感"不要求输入启动密码；启动密码保护的是 App 主界面。
5. 单个附件上限 10 MB；二维码拼图只适合约 34 KB 以内的附件，更大的请走 `.clink` 文件。
6. 通过聊天软件发送大段文本时，个别软件会截断过长文本；二维码图片和 `.clink` 文件不受影响。
